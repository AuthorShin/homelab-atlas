# Homelab Atlas v0.19.0

## Raster images become real vectors

Custom logos, group logos, and the app logo are now traced to SVG with [OpenVector](https://github.com/Microck/openvector) when they are uploaded. The tracing engine runs in a separate container that is reachable only from Atlas over the Compose network; images are never sent to an outside service.

SVG source files are already vectors and are stored as-is after safety validation. PNG, JPG, WebP, and ICO sources are converted to PNG in the browser when needed and traced to SVG. The traced app logo is also used as the browser tab icon when no project tab icon is saved. The project tab icon keeps its PNG pipeline, and background images stay raster.

If the vectorizer container is unavailable, logo and app-logo uploads fail with a clear error rather than silently storing a raster image.

## Convert images already uploaded

**File → Convert existing images to vectors** converts raster upload references and legacy raster data URLs used by custom logos, group logos, and the app logo. Files that are already SVG, theme backgrounds, and the PNG tab icon are skipped. The change is applied atomically to the open project and can be undone.

## Deployment

Both `compose.yaml` and `compose.release.yaml` now start two containers: `atlas` and `vectorizer`. The vectorizer publishes no host port. Atlas discovers it through `ATLAS_VECTORIZER_URL`. The released ZIP includes the vectorizer source and Dockerfile, and two images are published under the same version tags.

## Upgrade from 0.18.0

Recreate the containers with the new Compose file. The `atlas-data` volume is reused, including uploaded images and the autosaved default project. Open **File → Convert existing images to vectors** to trace logos that were uploaded before this release.

The project schema is unchanged at version 12. Open **File → Save project** before updating and keep the ZIP.
