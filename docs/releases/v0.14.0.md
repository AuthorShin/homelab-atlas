# Homelab Atlas v0.14.0

**Released 2026-11-23.** This release adds app-wide branding that every browser and device receives from the Atlas server.

## App branding

Open **Diagram settings → App branding** to set:

- **App name**: the label beside the logo in the editor and dashboard.
- **Browser tab title**: an optional custom title. Leave it empty to use the app name.
- **App logo**: upload PNG, JPG, WebP, SVG, or ICO up to 2 MB. Atlas stores a square PNG up to 128px and uses it as the header logo and browser-tab icon.

The name, title, and logo are saved in `branding.json` in the container's `atlas-data` volume and served by `/api/branding`. A new device or fresh browser profile receives the same branding without importing a project or creating a browser autosave. Changing branding does not edit the current project or the shared default project.

The app logo appears in the header and browser tab first. If no app logo is saved, Atlas uses the project's tab icon, then the default Atlas mark. The existing project tab icon remains under **Diagram settings → Diagram appearance → Project tab icon** for projects that want their own icon.

## Storage and safety

- Compose deployments continue to mount the `atlas-data` volume at `/data`.
- Branding writes require `X-Atlas-Branding: 1` and `application/json`, are limited to 200 KB, and are stored atomically.
- Reads and writes report a clear error when the data directory is unavailable. The editor and dashboard continue to work with default branding.
- The endpoint is not authenticated. Anyone who can reach Atlas can read or replace the branding, so keep Atlas on localhost or a trusted LAN.
- `docker compose down` keeps the volume. `docker compose down -v` removes the branding with the volume.

## Upgrade from 0.13.x

- The project schema stays at version 8. Existing projects, autosaves, default projects, and service links need no migration.
- Recreate the released container with the new Compose file. The existing `atlas-data` volume is reused, so the shared default project is kept. Branding starts with the default Atlas name and mark until you save it.
- Older Atlas versions ignore `branding.json`. Downgrading leaves the file in the volume; it is used again after upgrading.
- Older Atlas versions cannot open schema-version-8 projects. Keep a JSON backup before downgrading.

## Verification

Automated checks cover branding validation, the `/api/branding` API, fresh-browser persistence, fallback to the project tab icon, the editor and dashboard headers, static serving, release packaging, and documentation. The release workflow also verifies anonymous Linux AMD64 and ARM64 image pulls before creating the GitHub release.
