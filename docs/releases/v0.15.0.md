# Homelab Atlas v0.15.0

## Service groups

The device inspector's **Apps** tab now has up and down buttons beside each service group. Each group can also have an optional logo shown to the left of its name, including for unnamed groups. The per-device **Side-by-side groups** checkbox lays groups out using the **Columns** value from **Diagram appearance**: 1 → 1, 2 → 2, 3 → 3, 4 → 4.

## Project appearance

**Diagram settings → Diagram appearance** adds independent **Network row** and **VLAN row** controls (Top or Bottom, both defaulting to Top). A **Background image** is stored on the Atlas server and shown behind the editor and dashboard. **Custom CSS** is project text up to 20,000 characters, stored in project JSON and applied in the editor and dashboard. The Content-Security-Policy permits inline styles for this purpose. Custom CSS and the background image are not drawn into exported SVG or PNG files.

## Image uploads

New image uploads are stored in the `atlas-data` volume under `uploads/` and served from `/api/uploads`. This applies to app logos, project tab icons, custom logos, group logos, and background images. `POST /api/uploads` accepts PNG, JPG, WebP, SVG, or ICO bodies up to 2 MB with the `X-Atlas-Upload: 1` header; `GET` and `HEAD /api/uploads/<sha256>.<ext>` serve them with immutable caching. Uploaded images are referenced by URL rather than embedded as data URLs, and are inlined before export. Older data URLs in imported projects remain valid.

## Schema 9

The project schema moves from version 8 to version 9. Version 9 adds `css`, `background`, `networkRow`, `vlanRow`, `device.groupLayout`, and `group.logo`. Schema-8 projects migrate automatically and keep their service links and favicons. Schema 9 still has no `discovery` field, and older imports still discard legacy discovery data.

App branding remains app-wide server data in `branding.json`, separate from project JSON, with the same logo precedence: app logo, then project tab icon, then the default Atlas mark. Service links, favicons, app branding, custom CSS, and the background image are never part of an export.

## Upgrade from 0.14.x

Recreate the container with the new Compose file. The existing `atlas-data` volume is reused, so the default project, branding, and uploaded images are kept. Keep a JSON backup before downgrading, because older Atlas versions cannot open schema-9 projects.
