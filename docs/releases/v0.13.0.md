# Homelab Atlas v0.13.0

> **Previous release:** v0.13.0 made the default project shared by the Atlas server. See the [current release notes](/releases/v0.14.0) for app branding.

**Released 2026-11-22.** This release makes the default project shared by the Atlas server instead of one browser.

## A default project for every device

**File → Save as default project** now stores the current project in the container's `atlas-data` volume. A new device, browser, or fresh browser profile that has no autosaved project opens it instead of the included example. **File → Clear default project** removes it.

The default is still separate from autosave:

- A browser with an autosaved project keeps that project.
- A browser with no autosave loads the shared default and shows **Using default project**.
- The first edit creates a normal browser autosave.
- Older browser-stored defaults are used only when the server has no default.

The default is one optional project file. Atlas does not add accounts, a database, background sync, or collaborative editing.

## Storage and backups

- Compose deployments now mount the `atlas-data` volume at `/data`.
- `docker compose down` keeps the volume. `docker compose down -v` deletes the default with the volume.
- Running from source uses `data/` by default. Set `ATLAS_DATA_DIR` to choose another writable directory.
- If the data directory is not writable, Atlas still serves the editor and dashboard, but saving a default reports that storage is unavailable.
- Anyone who can reach the instance can read or replace the default. Keep Atlas on localhost or a trusted LAN.

## Upgrade from 0.12.x

- The project schema stays at version 8. Existing projects and browser autosaves need no migration.
- A browser default saved by 0.12.x remains usable as a fallback. To make an existing browser default available to new devices, open that project and choose **File → Save as default project** once.
- Recreate the released container with the new Compose file so the `atlas-data` volume is mounted.
- Older Atlas versions cannot open schema-version-8 projects. Keep a JSON backup before downgrading.

## Verification

The release workflow checks the Go and Node tests, documentation build, Compose files, schema-8 migration, static serving, the default-project API, and container save/clear behavior. The published image is checked anonymously for Linux AMD64 and ARM64 before the GitHub release is created.
